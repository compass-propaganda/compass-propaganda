# 오라클 평가 수트

자문에서 필요한 질문을 하고, 같은 사실에 같은 기준을 적용하며, 승인된 권장의 범위를 유지하는지 확인합니다. [사례](cases.json)는 가상 상황이며 교리나 새 권장이 아닙니다. 특정 문장을 정답으로 삼지 않고 사례별 조건과 허용 범위를 평가합니다.

## 평가 범위

| 묶음 | 확인할 행동 |
| --- | --- |
| clarification | 중요한 미확인 조건을 묻거나 가정을 명시하는가 |
| framing | 같은 사실에 찬성·반대 유도 표현만 바꿔도 기준을 유지하는가 |
| conversation | 추가 사실을 반영하고, 처음부터 같은 사실을 준 경우와 판단 기준이 일치하는가 |
| approved | 승인된 권장과 예외, Pn 충돌 규칙을 적용하는가 |
| principles | 성취의 의무를 추가하지 않고 개인의 삶을 존중하는가 |
| access | 원문을 확인하지 못한 상태를 승인된 권장 적용과 구별하는가 |

현재 수트는 공개된 개발·회귀 사례입니다. 별도의 미공개 평가 집합이나 대표 표본이 아니므로 점수를 오라클의 일반적 정확도나 성직자 일치도로 사용하지 않습니다. 반복 실행은 같은 입력에서의 변동을 보여주며, 독립된 사례 수를 늘리는 것은 아닙니다.

## 실행

```sh
node scripts/build-oracle.mjs
node scripts/eval-oracle.mjs --adapter evals/oracle/codex-adapter.mjs --model gpt-6-astra --output dist/evals/current
```

Node.js 20 이상과 로그인된 Codex CLI가 필요합니다. 다른 실행 파일은 `ORACLE_EVAL_CODEX` 환경 변수로 지정합니다. 응답 생성은 모델 사용량을 소비하므로 기본 CI에서는 실행하지 않습니다. `--repeat 3`으로 반복하거나 `--case missing-context`로 한 사례를 고를 수 있습니다. 결과 디렉터리는 덮어쓰지 않습니다.

기존 지침과 비교하려면 수정 전에 생성된 `oracle.md`를 보관하고 `--bundle 파일경로`로 지정합니다. 두 실행의 모델·추론 설정·자료·사례와 어댑터가 같은지 각 `manifest.json`에서 확인합니다. 소스 커밋과 별도로 묶음·사례·권장 원문·어댑터의 내용 해시를 기록하므로 커밋 전 변경도 식별할 수 있습니다.

이 실행기는 원문 자료를 고정하여 제공합니다. 배포용 프롬프트·skill에 권장을 동봉하는 것이 아니며, 실시간 검색이나 skill 자동 인식을 시험하지 않습니다. 전체 승인 권장 원문을 같은 조건으로 제공하고, 접근 실패 사례에는 제공하지 않습니다. 실제 서비스의 도구 연결·원문 조회는 별도로 확인합니다.

어댑터는 stdin으로 `{ model, instructions, context, sources, messages }`를 받고 stdout에 `{ text, ...실행정보 }` JSON을 반환하는 Node.js 프로그램입니다. 모델을 바꾸거나 다른 제공자를 시험하려면 이 계약의 어댑터를 사용합니다. 채점 기준과 이후 사용자 발언은 응답 생성 입력에 포함하지 않습니다. 후속 턴에는 실제로 생성된 앞선 응답을 전달합니다.

Codex 어댑터는 임시 작업 디렉터리에서 읽기 전용으로 실행하고, 사용자 설정·프로젝트 지침·설치된 skill 탐색·메모리·셸·웹 검색을 배제하도록 설정합니다. 공통 호스트 지침까지 제거한 순수 모델 실험은 아닙니다. 요청한 모델명과 추론 설정, CLI 버전·이벤트·사용량을 기록합니다. 요청한 모델명은 서버가 실제 제공한 모델의 인증 정보가 아닙니다. 비대화형 실행 옵션은 [공식 안내](https://developers.openai.com/codex/noninteractive/)를 따릅니다.

## 검토와 비교

`*.output.json`에는 실제 응답과 실행 정보가, `*.input.json`에는 해당 턴의 입력이 남습니다. `rubric.json`의 각 조건을 **통과·실패·판단 유보**로 검토하고 근거가 되는 응답 구절을 적습니다. 질문 수와 답변 길이는 부담을 살피는 보조 자료이며 짧다는 이유만으로 통과시키지 않습니다.

자문의 목소리는 질문과 제안의 이유가 신도의 상황과 교리에 연결되는지, 용어와 권한을 정확히 구별하는지로 검토합니다. 특정 어조나 종교적 어휘의 빈도를 정답으로 삼지 않습니다. AI나 구현 정보를 직접 묻는 질문에 정확히 답하는 것은 역할을 벗어난 것으로 평가하지 않습니다.

framing의 두 사례와 conversation의 마지막 응답은 함께 비교합니다. 표현 차이는 허용하지만 사실·선호가 같은데 반영한 가치나 행동 제안이 부당하게 뒤집히면 실패입니다. 새 사실 때문에 결론을 바꾸는 것은 허용합니다. 음식 선택 사례는 특정 음식의 건강 효과나 모든 상황의 정답을 정하지 않습니다.

실행 실패와 미응답은 의미 평가의 통과로 계산하지 않습니다. `summary.json`의 completed는 응답 생성 성공만 뜻하며 채점은 별도입니다. 전체 응답을 읽기 전, 또는 일부만 채점한 상태에서는 총점을 보고하지 않습니다. AI가 채점했다면 검토자와 모델을 밝히고, 사람의 검토를 거치지 않은 결과임을 표시합니다.

초기 비교는 같은 조건에서 기존·수정 지침을 각각 실행하고 항목별 차이를 검토합니다. 가능하면 응답의 판본을 가리고 순서를 바꿔 검토합니다. 개선 사례뿐 아니라 회귀와 질문 부담도 함께 기록합니다. 모델 자체의 변동과 지침의 효과를 구별하려면 반복 수와 별도 사례를 늘려야 합니다.

평가 입력·응답·실행 로그는 `dist/evals/`에 보관하며 정적 사이트와 오라클 배포본에는 포함하지 않습니다. 공개 보고가 필요하면 사적 정보와 실행 로그를 검토한 뒤 별도로 작성합니다.
